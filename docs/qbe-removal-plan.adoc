= QBE Backend Removal Plan
:toc: left
:toclevels: 2

== Status

[cols="1,3"]
|===
| Decision | Remove the QBE backend; native code generation (x86-64, arm64) becomes the only backend.
| Phase 0 | Done: `--help` marks `--backend qbe` and `BLAISE_BACKEND=qbe` as deprecated; the deprecation was announced to the community.
| Phase 1 | In progress -- decouple the test suite from QBE.  1a and 1b done; 1c in progress.
| Phase 2 | Not started -- delete the backend.  Target: release v0.15.0, which also
makes the macOS arm64 port usable.
| Phase 3 | Not started -- documentation.
|===

== Rationale

The QBE backend was essential while the native backend was being built: a
second, independent lowering made it possible to compare behaviour, study
generated code, and bootstrap the compiler before the native toolchain could
self-host.  That role has ended.

* *Self-hosting no longer needs it.*  The CI rolling bootstrap from the
  current anchor release is native-only and uses neither QBE nor a C compiler.
* *It contradicts the toolchain goal.*  Blaise produces executables with its
  own assembler and linker and needs no external tools or libraries; QBE is
  the last component that requires an external assembler, a C compiler and a
  libc link.
* *It is a second backend to keep in step.*  The QBE backend is about 19,550
  lines, against about 40,300 lines for all native code generation.  Every
  language change has to be lowered twice, and the two drift: QBE-specific
  silent miscompiles are part of why `tools/flag-coverage` exists, and recent
  test work found several constructs QBE no longer lowers correctly.
* *Three native platforms now provide the cross-checking.*  The same e2e
  programs run on x86-64 (Linux, FreeBSD) and arm64 (macOS).  Disagreements
  between the two native ISAs have exposed real defects; agreement between QBE
  and x86-64 never caught those.
* *There are no known users.*  The native backend has been the default since
  v0.12.0.

== Coverage QBE provides today, and its replacement

|===

| IR unit tests: substring assertions on generated QBE IR (`GenIR`)
| 1,092 assertions in 78 files

| QBE-only e2e paths: tests that pin the QBE backend (`beQBE`, `QBEOrNative()`)
| about 60 references, mostly `cp.test.e2e.leakcheck.pas` and `cp.test.e2e.base.pas`
| Audit each: run on native, or delete if it tests QBE itself.

| A second lowering to compare when debugging
| tooling
| Compare `--emit-asm` output for x86-64 and arm64 of the same source; pdr and

| Readable IR for studying code generation

| `--emit-asm` on both ISAs; a short "reading the native assembly" section in

| strategic

== Phase 1 -- decouple the test suite

Phase 1 changes tests only; the QBE backend stays in the tree and in the
compiler until Phase 2.

=== 1a. Native-only e2e default

* `AllBackends` (the set behind `AssertRunsOnAll` and `AssertRTLRunsOnAll`)
  becomes the native backends the host can run.  QBE leaves the default set.
* Explicit `AssertRunsOn([beQBE, ...])` calls keep working until the 1d audit
  removes them.
* Expected effect: e2e wall time roughly halves, and the e2e suite no longer
  needs `vendor/qbe` or a C toolchain.

=== 1b. One shared unit-test harness

Every unit-test class currently carries its own copy of `GenIR` (78 copies),
and several carry their own `GenAsm`.  Before migrating assertions, add a
shared harness unit (for example `cp.test.harness`) providing:

* `Analyse(Src)` -- lex, parse and run the semantic pass, returning the
  program (for AST-annotation assertions) or raising the semantic error;
* `GenAsm(Src, Target)` -- generate native assembly for a given target
  (`linux-x86_64`, `macos-arm64`, ...) in-process.  Generating assembly text
  needs no toolchain, so cross-ISA assertions run on every host.

=== 1c. `GenIR` triage rules

Every `GenIR` assertion is classified into exactly one category.  The
deciding question is whether a wrong lowering would be visible when the
program runs.  If it would, running a program is the better test: thousands
of e2e programs and the self-hosting fixpoints already exercise the common
lowerings, and an assembly substring check adds brittleness (label names,
register choice) without catching anything they miss.

Front-end assertion::
The test checks that a program is accepted or rejected, or that the semantic
pass annotated the AST correctly, and the IR substring is only a proxy for
that.
+
Action: rewrite on `Analyse` / `SemanticError` -- assert the error message,
or the AST annotation (`ResolvedType`, `FieldInfo`, flags), directly.
+
Example: a test that compiles a program and asserts `call $Foo` appears,
when what it means is "the overload resolved to `Foo`".

Behaviour assertion::
The lowering decision changes what the program does: control flow,
comparisons, arithmetic, conversions, calls that happen or not.
+
Action: delete the assertion when an e2e test already covers the behaviour;
otherwise add a small e2e test (`AssertRunsOnAll`) that would fail under the
wrong lowering, then delete it.  Prefer inputs that discriminate -- negative
operands for signedness, both branches taken, boundary values.
+
Example: "`<` uses `csltw`" becomes an e2e test that compares negative
Integers and prints the results.

Code-generation assertion::
The decision is invisible when the program runs: optimisation shape
(register promotion, inlining, folding), the exact placement of ARC
retains and releases where a mistake would not leak or crash in a small
program, ABI and frame details, or a layout-sensitive bug whose symptom
cannot be reproduced reliably by running a program.
+
Action: port to `GenAsm` / `AsmMissing`.  Assert on BOTH x86-64 and arm64
whenever the decision is ISA-independent (decided); assert on one ISA only
when the shape is genuinely ISA-specific.
+
Example: "the old element is released before the store" -- assert the release
call precedes the store on both ISAs.

QBE-only assertion::
The test pins QBE syntax with no behaviour behind it: `alloc16` frame sizes,
QBE type letters (`function w $F`), QBE temporaries such as `%_var_Result`,
the order QBE functions are emitted in, QBE-specific workarounds.  Labels
and jumps are not QBE-only: they stand in for control flow, which is a
behaviour assertion.
+
Action: mark it `QBE-only` in a comment and leave it on `GenIR`; it is
deleted in Phase 2 together with the backend.

When an assertion fits none of the categories, or the right one is unclear,
leave it in place and add it to the open questions at the end of this plan.

=== 1d. QBE-only e2e audit

Review every `beQBE` / `QBEOrNative()` reference:

* tests of language behaviour run on native instead;
* tests of the QBE backend itself (QBE IR validity, QBE toolchain discovery)
  are marked for deletion in Phase 2;
* `cp.test.e2e.leakcheck.pas` (66 tests) gets particular care: leak checks
  must keep running on every native backend.

=== Exit criteria

* `GenIR` call count is zero outside tests marked for deletion.
* No e2e test depends on the QBE backend except those marked for deletion.
* The full suite passes on Linux and FreeBSD CI with QBE absent from the
  default backend set; the macOS gates stay green.

== Phase 2 -- remove the backend

* Delete `blaise.codegen.qbe.pas` and `blaise.codegen.qbe.driver.pas`.
* Remove the QBE branches from `Blaise.pas`, `blaise.codegen.driver.pas`,
  `blaise.codegen.pas`, `blaise.codegen.target.pas`, `blaise.frontend.opts.pas`
  and `uToolchain.pas`; review the QBE references in the semantic and AST
  units (mostly comments and QBE-only annotations).
* `--backend qbe` becomes a hard error naming v0.15.0 as the release that
  removed it; decide whether `--backend` remains at all.
* Remove `--emit-ir` (decided: no replacement; `--emit-asm` covers inspection).
* Delete `vendor/qbe/` and `scripts/fixpoint.sh` (the QBE fixpoint); remove the
  QBE references from `scripts/rolling-bootstrap.sh`,
  `scripts/fixpoint-native.sh`, `scripts/fixpoint-native-internal.sh` and
  `scripts/BOOTSTRAP.adoc`.
* CI: remove the "Build vendored QBE" step and `BLAISE_QBE` from
  `.github/workflows/bootstrap.yml` and the FreeBSD job.
* Tools: drop the QBE column from `tools/flag-coverage` (and reset its status
  file); check `tools/bif-coverage` for QBE-only fields.
* Delete the tests marked QBE-only in Phase 1.
* Tag the last release that contains the backend, so it remains buildable.

== Phase 3 -- documentation

* Record the decision and its rationale in `docs/toolchain-independence.adoc`
  (and cross-reference it from `docs/language-rationale.adoc` if appropriate).
* Update `README.adoc`, `docs/testing-strategy.adoc` and `docs/design.adoc`.
* Sweep the remaining design documents that mention QBE; historical design
  notes may keep their QBE references with a short "historical" note rather
  than being rewritten.
* Update the private `CLAUDE.md` notes: the "IR unit test + E2E test" rule
  for new features becomes "asm or semantic unit test + E2E test", and the
  debugging guidance compares x86-64 and arm64 instead of QBE and native.

== Working method

* Work in a git worktree branched from `master`, one test file per commit.
* Each commit: the migrated tests pass, the full suite shows no new failures,
  and the linked-binary fixpoint holds.
* Validate on a `ci/**` branch before `master`, as for all pushes.
* Keep the progress table below current in the same commit as the migration.

== Decisions

. Code-generation assertions are made on both x86-64 and arm64 wherever the
  lowering decision is ISA-independent.
. `--emit-ir` is removed in Phase 2, with no replacement; `--emit-asm` is the
  inspection tool.
. The backend is removed in release v0.15.0 -- the same release that makes the
  macOS arm64 port usable.  The deprecation was announced with v0.12.0.
. A `GenIR` assertion whose behaviour is visible at run time becomes an e2e
  test (or is deleted when one exists), not an assembly check; `GenAsm` is
  kept for decisions a running program cannot observe (1c, revised after the
  first file).
